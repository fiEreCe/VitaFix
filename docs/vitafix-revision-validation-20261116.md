工作区开始时 git status 为空。原四项缺陷均存在：draftRevision 仅消费首条事实，引用全部事实，缺少结果时补写默认产出；repairRevision 忽略候选与 findings 并重复生成。

已有修改已保留：解析事实默认待确认；confirmed/corrected 才能进入生成；补充事实确认后仅替换当前任务 baseFactId，纠正版本使用 originalFactId；一次自动修复；三次用户重试；独立语义审核失败保留候选，重试只审核；blocked/unavailable 无法采用。固定评测的 E2E 用例注入候选，并未测试真实生成。

调用链：parseResume/buildSupplementFacts → matchEvidence → task.factIds → 用户核对 → _confirmedFactsForTask → calculateSufficiency(mergeFacts) → draftRevision → 确定性 guardrails → 独立语义审核 → 一次 repairRevision → 相同审核入口 → 用户采用及 handoff。多轮补充以新事实保存，结构字段包括 action/context/contribution/method/result/quantity/quantityType；确认后任务引用最新版本。补充评估与新版本现在仅继承最近事实，避免跨项目覆盖式合并。充分度仍复用原策略，生成额外要求相关确认事实，不足时沿用失败和人工处理入口。

采用确定性摘录方案：无需新增生成调用，不添加事实以外的动词或结果；用已有中文重叠与技能同义词选择相关种子，补入明确相同 context 的互补事实。每条事实独立成句，重复场景名以保持归属，不把不同记录的行动和结果连成因果。factRefs 对应实际输出的记录，requirementRefs 仅当前要求。保留原结构字段；补回原文中的课程项目、团队和参与限定；估算数字补约，未确认数字安全失败。无上下文的互补事实不会推测归属，需用户补充或人工处理。

修复对已知风险 findings 从已确认事实重建候选（数字、归因、职责、无依据主张、语义无关等）；不从原候选沿用任何未证实主张。使用原候选检测文本与引用均无变化的情况，明确失败；未知 finding 也安全失败。没有修改审核标准或自动修复次数。属于保守整体重建，不是局部润色；无法消除事实自身矛盾时仍由审核阻断。
