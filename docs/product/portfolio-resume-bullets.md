# 三条简历描述 — 精投助手求职作品

> 三条均基于真实实现与可复核测量结果。测量数据来自仓库内固定评测与自动化测试（命令与基线见 [交接文档](./11-development-handoff-2026-07-27.md)），未虚构任何指标。

## 描述一（主推 · 产品 + AI 工程）

**独立构建"证据驱动的 AI 简历教练"（精投助手）：让 AI 简历建议可追溯、可审核、可停止**

从零独立完成全栈设计与开发（Vue 3 / Vite / Vant、Express 5 / Mongoose 9 / MongoDB、DeepSeek API）。产品核心是把"AI 改简历"从黑盒重写改为教练式闭环——JD 要求 → 用户真实事实 → 充分度判断 → 动态追问确认 → 候选生成 → 强制事实审核 → 用户最终决定 → 修改效果验证。将 Agent 异步流程做成状态机，支持崩溃恢复（原子 claim + 租约 + 心跳续租）与用户数据归属隔离（设备 ID）。自动化基线：后端 114 项测试、前端 15 项契约 + 36 项单元测试、生产构建全部通过。

## 描述二（技术难点 · AI 安全护栏）

**设计两层 AI 事实安全系统，用 42 个固定评测用例把"AI 编造简历"挡在门外**

针对大模型改简历时的系统性夸大（"参与"写成"主导"、"学习"写成"使用"、凭空补数字），实现确定性规则 + 独立语义审核两层防线：确定性规则拦截未确认数字、跨用途数字（"20 位用户"误用为"营收增长 20%"）、职责扩大、虚构证书/技能/上线状态；独立语义审核拦截与引用事实无最低语义重叠的内容。审核异常、超时或格式非法一律降级为 `unavailable`，绝不默认通过。配套 12 个端到端 + 30 个原子固定评测用例，42/42 通过，任一红线被误放行即构建失败。

## 描述三（工程闭环 · 修改验证 + 浏览器验证）

**实现"改—验证—再改"闭环与多端响应式交付**

- **修改效果验证**：用户每轮修改后，系统基于一次异步语义评估计算 Diff、证据覆盖变化与 `changeOutcome`（改善/持平/回退），与 `safetyStatus`（事实安全）独立判定；每次验证追加不可变历史记录，用户再次编辑只使当前验证失效、不覆盖旧记录；风险内容仅在用户显式确认后进入 `completed_with_risk`。
- **响应式重构**：移除 480px 手机壳，按 600/900/1200px 断点适配手机/平板/电脑，Agent 工作台电脑端双栏 + 宽屏证据上下文栏；落实键盘焦点、44px 触控目标、降动效/降透明度/高对比降级、200% 缩放无横向溢出。Playwright 在 390×844 / 768×1024 / 1440×1000 三视口 × 8 路由验证 31 项通过、0 失败。
