# 精投助手页面产品规格

## 1. 文档目标

定义目标 MVP 各页面的目标、信息结构、主要操作、状态、跳转和页面级验收。业务算法引用模块规格，领域状态引用领域模型。

## 3. 通用页面规则

### 3.1 导航

- 页面标题使用任务语言，不使用内部对象名。
- 返回按钮遵循业务来源；深链接无来源时返回工作台或所属岗位版本默认页。
- 岗位版本页面持续显示公司、岗位和当前进度，避免用户混淆多个版本。

### 3.2 加载

- 首次加载使用骨架或明确的步骤说明。
- AI 长任务显示当前阶段，不展示虚假的精确百分比。
- 用户离开 AI 处理页不取消后台任务。

### 3.3 自动保存

- 用户输入和选择以草稿形式自动保存。
- 保存中、已保存、保存失败三个状态必须可感知。
- 保存失败时不得静默跳转；允许重试或复制未保存文本。

### 3.4 反馈

- 成功反馈说明“保存了什么”和“下一步是什么”。
- 错误反馈说明原因、已保留的数据和可执行动作。
- 删除、覆盖已确认事实、重新解析 JD 等高影响操作必须二次确认。

### 3.5 状态

所有页面至少定义：加载、正常、空、部分完成、失败、无权访问和对象不存在。具体提示见异常文档。

## 4. P-001 工作台

### 页面目标

让用户快速开始或继续一份岗位投递，同时看到职业证据库是否已建立。

### 页面结构

| 区域 | 内容 |
|---|---|
| 顶部摘要 | 产品定位、职业证据库状态、主要 CTA |
| 继续处理 | 最近一个未完成岗位版本、当前步骤、待处理数量 |
| 岗位版本列表 | 公司、岗位、方向、状态、更新时间、检查结果 |
| 空状态 | 导入简历并建立证据库 |
| 隐私提示 | 当前身份方式、数据用途和保留期限链接 |

### 主要操作

| 操作 | 条件 | 结果 |
|---|---|---|
| 导入简历 | 无基础简历 | 跳转 P-010 |
| 新建岗位版本 | 已有基础简历且满足建档门槛 | 跳转 P-020 |
| 继续处理 | 有未完成版本 | 跳到该版本最后一个有效步骤 |
| 打开已完成版本 | 版本存在 | 跳转 P-042 |
| 重命名 | 名称非空且不超过 50 字 | 更新版本名称 |
| 删除 | 二次确认 | 删除版本及其表达层数据，不删除共享事实 |

### 页面验收

- 无历史、加载失败、部分加载失败均有可操作状态。
- 版本列表只显示当前用户/设备有权访问的数据。
- 当前 Demo 的“历史分析总分”在目标版降级为辅助信息，不作为卡片主要视觉。

## 5. P-010 简历导入

### 页面目标

接收一份现有简历并生成可确认的结构化解析结果。

### 输入方式

| 方式 | 规则 |
|---|---|
| 粘贴文本 | 非空，建议上限 20,000 字 |
| 上传 PDF | 最大 20MB；扫描版无法提取时提示替代方案 |
| 上传 DOCX | 最大 20MB |
| 上传 TXT | 最大 20MB，按 UTF-8 解析 |
| `.doc` | 目标 MVP 明确不支持，提示转换；前后端规则需统一 |

### 主要操作

- “解析简历”：输入有效时可用，创建解析任务。
- “重新选择”：替换尚未确认的导入草稿。
- “取消”：返回工作台；已上传文本按隐私规则处理。

### 页面状态

- 解析中：展示正在提取文本/识别板块。
- 解析失败：保留已输入文本，支持重试、改用粘贴或重新上传。
- 文件不支持/过大：在上传前阻止并给出明确限制。
- 无文本：禁用提交。

## 6. P-011 简历解析确认

### 页面目标

让用户校正 AI 解析结果，并明确哪些内容已进入职业证据库。

### 页面结构

按个人信息、教育、实习、项目、校园/社团、竞赛/证书/课程和技能分组。每项展示解析内容和原文定位。

### 字段与操作

| 操作 | 行为 |
|---|---|
| 编辑 | 修改解析字段，不直接改原始上传文件 |
| 新增 | 补充遗漏板块或经历 |
| 删除 | 从待导入内容移除；保留原始文本审计按隐私策略确定 |
| 标记解析错误 | 用于质量评测，不自动训练模型 |
| 确认导入 | 建立基础简历和初始证据卡 |
| 重新解析 | 二次确认后替换未确认解析草稿 |

### 必填规则

- 至少包含一段教育、经历、项目、校园、课程或竞赛信息。
- 空技能列表不阻止导入。
- 个人联系方式不是产品核心字段，允许为空并应最小化展示。

## 7. P-012 职业证据库

### 页面目标

集中管理可跨岗位复用的真实经历、技能证据和确认状态。

### 页面结构

| 区域 | 内容 |
|---|---|
| 概览 | 已确认经历数、待深挖数、待确认事实数 |
| 经历列表 | 类型、名称、时间、证据强度、关联能力 |
| 技能列表 | 技能、使用场景、关联经历、证据强度 |
| 待办 | 推荐深挖经历、投递过程中新增的待确认事实 |

### 筛选

类型、确认状态、证据强度、最近更新。能力标签用于辅助筛选，不允许用户仅通过勾选标签制造证据。

### 操作

新增经历、打开详情、编辑、删除、创建岗位版本。删除被岗位版本引用的事实时，必须展示影响并使相关表达进入“来源失效”状态。

## 8. P-013 经历详情与深挖

### 页面目标

把一段笼统经历补充为可用于岗位表达、可解释且有来源的事实集合。

### 信息结构

- 基本信息：名称、类型、时间、背景。
- 目标与问题。
- 用户个人角色和责任边界。
- 关键行动、判断与方法。
- 工具、协作对象、困难及处理。
- 结果、数字、团队成果和证明材料。
- 来源、确认状态和关联岗位。

### 追问规则

一次只问一个高价值缺口；优先补充当前岗位需要的信息。数字、团队成果和个人归属必须单独确认。

### 操作

保存草稿、确认事实、标记“不记得/无法证明”、完成经历、下一段、返回来源页面。无法证明的信息可以保留为备注，但不能成为绿色证据。

## 9. P-020 JD 输入

### 页面目标

接收目标 JD 原文并创建岗位版本草稿。

### 输入与规则

- 文本粘贴：非空，上限建议 10,000 字。
- 截图 OCR：JPG/PNG，最大 10MB；OCR 后必须允许编辑原文。
- 公司和岗位名可由用户提前填写，也可由解析结果补全。

### 主要操作

“解析 JD”仅在文本有效时可用。OCR 不自动提交解析。解析失败时保留文本并支持重试。

## 10. P-021 JD 解析确认

### 页面目标

在证据匹配前确认系统对岗位的理解。

### 展示内容

| 内容 | 可编辑 | 说明 |
|---|---|---|
| 公司与岗位 | 是 | 用于版本命名 |
| 岗位方向 | 是 | AI/C 端/B 端/增长/数据/其他 |
| 是否适合应届生 | 是 | 显示判断依据和不确定性 |
| 主要职责 | 是 | 来自 JD |
| 五类岗位要求 | 是 | 门槛、工具方法、产品能力、协作推动、行业场景 |
| 必须项/加分项 | 是 | 用户可纠正 |
| 重要程度 | 是 | 核心/重要/一般 |

### 操作

- 确认并匹配：所有核心要求已有分类后可用。
- 返回修改原文：回 P-020，保留解析结果。
- 重新解析：覆盖当前解析草稿，已确认后修改则触发地图失效提示。

## 11. P-030 岗位要求—证据地图

### 页面目标

回答岗位最看重什么、用户有什么真实证据，以及缺口属于表达问题还是能力问题。

### 列表字段

岗位要求、类型、重要程度、当前证据、证据强度、匹配状态、问题诊断、推荐下一步。

### 匹配状态

- 强证据：可直接进入修改任务。
- 有相关经历但表达弱：进入高收益修改任务。
- 可能做过待确认：进入 P-013 补充事实。
- 无证据：标记真实能力缺口，不生成虚假表达。

### 操作

筛选核心要求/状态/类别；查看证据来源；补充事实；确认无证据；进入任务列表。总分仅作辅助摘要。

## 12. P-031 修改任务列表

### 页面目标

让用户按收益和风险处理修改，而不是从头到尾盲目重写整份简历。

### 任务卡

显示优先级、对应 JD、当前缺口、事实状态、预期收益、教学模式和完成状态。

### 分组

高优先级、中优先级、不建议修改、已完成、已跳过/有风险。

### 操作

打开任务、切换快速优化、重新排序同优先级任务、进入组装。缺少事实的任务不能直接批量生成。

## 13. P-032 单条修改工作台

### 页面目标

完成一条可追溯的岗位定制修改。

### 固定上下文

- 对应 JD 要求及重要度。
- 当前简历原文。
- 已找到的事实及证据等级。
- 当前问题和需要补充的信息。

### 编辑区

- 事实追问与用户确认。
- AI 辅助等级：示范、提示、独立。
- 稳妥表达、强化表达或用户自写文本。
- 修改理由摘要和事实来源映射。
- 接受、编辑、拒绝、修正事实、撤销。

### 完成条件

- 最终采用文本已保存。
- 所用事实均为已确认或按黄色证据规则明确归因。
- 修改记录完整。
- 阻断审核无红色问题。

## 14. P-040 岗位简历组装

### 页面目标

查看针对当前岗位组装后的完整简历内容，并理解每处变化。

### 两种视图

- 简历视图：按最终顺序展示内容，支持段落编辑和复制。
- 修改视图：展示原文、修改后、JD 要求、事实来源、修改原因和采纳状态。

### 组装规则

保留未修改内容；替换已确认段落；按岗位相关性调整经历顺序；突出有证据技能；标记风险和未完成项。MVP 不提供完整 Word/PDF 排版。

## 15. P-041 投递前检查

### 页面目标

在用户复制或结束前，发现真实性、岗位相关性和表达质量问题。

### 检查分组

| 分组 | 示例 | 严重级别 |
|---|---|---|
| 真实性 | 无来源事实、未确认数字、团队成果写成个人成果 | 阻断 |
| 相关性 | 核心 JD 无回应、只有关键词无证据 | 阻断或警告 |
| 表达质量 | 空泛、过长、重复、模板化 | 建议 |

### 操作

打开问题、跳转修复、确认保留警告、重新检查、完成。阻断问题未解决时不能进入 P-042。

## 16. P-042 岗位方案完成页

### 页面目标

交付完整岗位投递方案，并为后续投递提供入口。

### 展示内容

1. 可复制的岗位简历版本。
2. 修改记录摘要。
3. 真实能力差距和学习建议。
4. 本次学习结果与下一次建议辅助等级。

### 操作

复制全部/单段、返回编辑、查看证据来源、返回工作台、基于相同简历创建新岗位版本。

## 17. P0 页面待决策
