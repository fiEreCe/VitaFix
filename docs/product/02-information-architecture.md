# 精投助手信息架构与页面导航

## 1. 文档目标

定义目标 MVP 的页面层级、页面职责、路由、入口、出口和访问条件。详细交互见页面规格，业务判断见模块规格。

## 2. 架构原则

1. 以“岗位投递版本”作为用户主任务，以“职业证据库”作为长期底座。
2. 首页优先帮助用户继续未完成投递或创建新投递，不以总分作为核心入口。
3. JD、证据地图、任务、简历版本和最终检查都从属于一个岗位版本。
4. 职业证据是跨岗位复用的数据；推荐表达和修改记录仅属于一个岗位版本。
5. 移动端优先，桌面端保持可用；当前 480px 居中方案可复用，但正式断点和布局由设计评审确认。

## 3. 目标页面树

```text
P-001 工作台
├─ P-010 简历导入
│  └─ P-011 简历解析确认
├─ P-012 职业证据库
│  └─ P-013 经历详情与深挖
├─ P-020 新建岗位版本 / JD 输入
│  └─ P-021 JD 解析确认
└─ 岗位版本
   ├─ P-030 岗位要求—证据地图
   ├─ P-031 修改任务列表
   │  └─ P-032 单条修改工作台
   ├─ P-040 岗位简历组装
   ├─ P-041 投递前检查
   └─ P-042 岗位方案完成页
```

## 4. 全局导航

MVP 建议保留两个一级入口和一个主操作：

| 导航项 | 页面 | 显示条件 | 说明 |
|---|---|---|---|
| 投递 | P-001 工作台 | 始终 | 查看岗位版本、继续未完成任务 |
| 证据库 | P-012 职业证据库 | 已导入简历后 | 查看和维护长期职业证据 |
| 新建岗位版本 | P-020 JD 输入 | 已有基础简历；无简历时转 P-010 | 全局主操作 |

岗位版本内使用局部步骤导航：证据地图 → 修改任务 → 简历组装 → 投递检查。未满足前置条件的步骤可查看状态说明，但不能绕过必要确认。

## 8. 返回、恢复与深链接

- 所有输入和编辑页面在内容变化后自动保存草稿；返回不丢失已提交或已确认数据。
- 浏览器返回优先返回上一个业务页面；若从深链接进入，则返回所属岗位版本默认页。
- P-013 从证据地图进入时，完成或取消后返回 P-030；从证据库进入时返回 P-012。
- P-032 从最终检查问题进入时，完成后返回 P-041；从任务列表进入时返回 P-031。
- 刷新后根据对象状态恢复当前页，不依赖仅存在于内存或 query 的临时 ID。
- 无效或无权访问的对象统一进入可恢复错误态，并提供“返回工作台”。
