# 精投助手 MVP 验收标准

## 1. 文档目标

定义 MVP 功能、页面、数据、AI、异常、隐私和非功能完成标准。本文档中的 P0 阻断项未通过时不得发布真实用户版本。

## 2. 验收范围

### 包含

- 产品岗范围。
- 简历导入与证据库。
- JD 解析确认。
- 证据地图和修改任务。
- 单条修改和教学练习。
- 简历组装、复制和投递检查。
- 进度恢复、历史岗位版本和删除。

### 不包含

- 非产品岗位。
- Word/PDF 完整排版与导出。
- 求职信、面试题、职位搜索和自动投递。
- 复杂账号、组织或多人协作。
- 模型微调。

## 3. 测试准备

- 至少 30 个应届产品岗标准案例，目标 50 个。
- 覆盖 AI、C 端、B 端、增长、数据产品。
- 每例含 JD、原简历/证据、预期重点、允许表达、禁止内容和评分依据。
- 包含文件失败、信息不足、团队成果、估算数据、扫描 PDF、模糊 JD 等边界案例。
- 测试环境使用与生产一致的模型、Prompt、Schema 和规则版本。

## 4. 端到端验收

### AC-E2E-001 完成一份岗位投递方案

```gherkin
Given 用户没有职业证据库
When 用户导入并确认一份有效简历
And 确认至少一段代表经历
And 创建岗位版本并确认一条产品岗 JD
And 完成至少一条 AI 示范修改
And 完成至少一条独立修改
And 组装岗位简历并完成投递前检查
Then 系统生成可复制的岗位简历版本
And 每条修改都能追溯到 JD 要求和已确认事实
And 完成页展示修改记录、能力差距和学习结果
And 不存在真实性 blocker
```

### AC-E2E-002 第二次投递复用证据

```gherkin
Given 用户已有经确认的职业证据库
When 用户创建第二个岗位版本并确认新 JD
Then 系统复用已有事实
And 只询问新岗位需要但证据库缺少的信息
And 不要求用户重复填写已确认事实
```

### AC-E2E-003 无真实证据

```gherkin
Given 一条核心 JD 要求在职业证据库中没有证据
When 用户确认自己没有做过相关任务
Then 系统将其标记为真实能力缺口
And 不生成声称用户做过该任务的简历表达
And 最终方案说明该缺口对岗位的影响
```

## 5. 模块功能验收

### 5.1 职业证据库

- [ ] 支持粘贴文本、PDF、DOCX、TXT。
- [ ] 不支持的格式和大于 20MB 文件在上传阶段获得明确提示。
- [ ] 解析结果可编辑、添加、删除和确认。
- [ ] 未经确认的解析内容不作为绿色证据。
- [ ] 经历卡可保存角色、行动、方法、协作、结果、团队成果和来源。
- [ ] 技能没有使用场景时不生成业务成果。
- [ ] 修改已确认事实后需要重新确认。
- [ ] 删除事实会提示并更新所有引用。

### 5.2 岗位版本与 JD

- [ ] 无基础简历时创建岗位版本会引导导入并可返回。
- [ ] JD 支持文本和截图 OCR，OCR 后可编辑。
- [ ] 岗位方向、五类要求、重要度、必须/加分项可确认和纠正。
- [ ] 未确认 JD 不进入证据匹配。
- [ ] 重新解析已确认 JD 会提示下游结果失效。
- [ ] 删除岗位版本不删除职业证据。

### 5.3 证据地图与任务

- [ ] 每条核心要求具有匹配状态、证据来源、诊断和下一步。
- [ ] 表达缺口与真实能力缺口可区分。
- [ ] 无证据要求不生成表达任务。
- [ ] 任务包含优先级、原因、来源、收益和状态。
- [ ] 事实变化只重新计算相关项。

### 5.4 修改工作台

- [ ] 固定展示 JD、原文、事实和缺口。
- [ ] 证据不足时先追问。
- [ ] 稳妥和强化表达都不增加事实。
- [ ] 每条建议展示来源和可核验理由。
- [ ] 支持接受、编辑、拒绝、修正事实和撤销。
- [ ] 独立模式不提前显示答案。
- [ ] 最终采用文本和修改记录持久化。

### 5.5 组装与检查

- [ ] 组装只使用基础简历和已确认修改。
- [ ] 简历视图和修改视图内容一致。
- [ ] 支持单段和整份复制。
- [ ] 真实性、相关性和表达质量检查均执行。
- [ ] blocker 未解决时不能完成。
- [ ] 能力缺口不自动写入简历。

## 6. 页面与交互验收

- [ ] 信息架构中的 P0 页面均可通过合法路径到达。
- [ ] 直接访问无效/无权路由不会泄露对象信息。
- [ ] 返回、刷新和重新打开能恢复到正确步骤。
- [ ] 加载、空、错误、无权和部分完成状态均有可执行动作。
- [ ] 保存失败不会静默丢失文本。
- [ ] 高影响删除和覆盖操作均二次确认。
- [ ] 当前岗位公司、名称和进度在岗位版本页面持续可见。

## 7. AI 质量验收

### P0 硬门槛

| 指标 | 门槛 | 说明 |
|---|---|---|
| 红色无依据事实生成 | 0 | 固定评测集任何一次出现即阻断 |
| 团队成果错误归为个人 | 0 | 固定评测集任何一次出现即阻断 |
| 未确认数字进入可采用表达 | 0 | 固定评测集任何一次出现即阻断 |
| 引用不存在/跨用户事实 | 0 | 安全与完整性阻断 |
| Schema 不合法结果直接展示 | 0 | 必须由服务层拦截 |

### 待基线后冻结

JD 要求识别准确率、证据匹配准确率、建议可操作性、关键词堆砌率、盲评胜率和大幅二次修改率，在 30—50 个案例完成基线评测后由产品、AI 和测试共同确定数值。

### 回归

- [ ] 模型、Prompt、Schema 或规则变化时自动运行固定评测集。
- [ ] 评测结果记录版本并可与上一版本比较。
- [ ] 失败案例进入缺陷库并能复现输入对象版本。

## 8. 数据与权限验收

- [ ] 所有用户拥有对象均关联 userId。
- [ ] 所有详情、状态、修改和删除接口校验所有权。
- [ ] 通过其他用户对象 ID 无法读取或修改数据。
- [ ] 重复请求不会创建重复岗位版本、任务或修改记录。
- [ ] 事实层和表达层分离；岗位变化不改写事实。
- [ ] 来源删除会使相关表达和检查状态失效。
- [ ] 用户确认、修改和删除有审计记录。

## 9. 异常恢复验收

- [ ] AI 网络、429、5xx 和 Schema 失败只重试当前步骤。
- [ ] 达到自动重试上限后提供手动重试。
- [ ] 中途关闭页面后已确认事实和草稿仍可恢复。
- [ ] 后台分析完成后工作台状态更新。
- [ ] 解析或组装失败不删除已确认数据。
- [ ] 服务端错误响应不包含密钥、堆栈或完整模型输出。

## 10. 隐私验收

- [ ] 页面说明收集目的、第三方 AI 使用和数据保留规则。
- [ ] 实现的数据保留期限与用户文案一致。
- [ ] 未获单独授权不将用户内容用于训练。
- [ ] 普通日志不记录完整简历、JD、联系方式和模型完整输出。
- [ ] 用户可删除单条经历、岗位版本和全部职业档案。
- [ ] 删除操作按规则处理关联对象。

数据保留期限和账号策略未确认前，本节不能签字通过。

## 11. 非功能验收

### 性能

- 页面普通数据加载应有明确响应；具体 P95 门槛由技术评审确定。
- AI 任务在等待期间不阻塞页面导航。
- 当前 AI 超时上限 120 秒可作为技术基线，不代表目标体验门槛。

### 兼容性

- 移动端优先。
- 桌面端可用，当前 480px 居中模式可作为最低基线。
- 支持团队确认的主流 Chrome、Edge、Safari 版本。

### 可访问性

- 核心操作可键盘访问。
- 状态不只依赖颜色表达。
- 表单、错误和按钮具有可读标签。
- 动画遵循 reduced-motion。

### 可观测性

- AI 任务、保存失败、权限拒绝和删除操作有结构化日志。
- 核心漏斗业务成功事件可查询。
- P0 安全事件可告警。

## 12. 上线阻断条件

- [ ] 核心端到端流程不可完成。
- [ ] 已确认事实或用户编辑文本丢失。
- [ ] 存在跨用户访问。
- [ ] AI 生成无来源事实、错误归因或未确认数字。
- [ ] blocker 可被绕过进入完成状态。
- [ ] 隐私文案和实际保留策略不一致。
- [ ] 删除全部档案不可用。
- [ ] P0 待决策仍未形成明确产品结论。
