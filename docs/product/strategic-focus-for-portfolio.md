# 精投助手：作为求职作品，该集中做什么

## 核心判断

当前项目有一个根本矛盾：**产品文档和实际代码指向两个完全不同的产品。**

| | 当前 Demo（代码） | 目标 MVP（PRD） |
|---|---|---|
| 定位 | 通用简历-JD 评分工具 | 应届生产品岗"证据驱动"简历教练 |
| 核心产出 | 分数 + 雷达图 | 可追溯的修改记录 + 能力差距 + 学习结果 |
| 数据模型 | 单次 Resume/JD/Analysis | 职业证据库 + 多岗位版本 |
| 开发量级 | 已完成 | 需要重写数据模型、全部页面、全部 AI 逻辑 |

PRD 里定义的 MVP 是一个**完整团队 3-6 个月**的工作量。一个人不可能在求职季之前把它做完。

**策略不是"做什么功能"，而是"做什么功能能让面试官在 30 分钟内觉得你强"。**

---

## 核心原则：展示深度，而非广度

面试官看一个项目，30 秒决定是否继续看，5 分钟形成判断。他们不会看完你的 PRD。他们关心的是：

> "这个人在有限的资源下，做出了什么聪明的取舍？解决了什么真正的难题？"

一个"功能很多但每个都很浅"的项目 = 平庸。一个"功能不多但每个都体现了深度思考"的项目 = 印象深刻。

---

## 建议集中火力做这 4 件事

### 1. 证据追溯链（Evidence Traceability）—— 杀手功能

**为什么这是最重要的：** 市面上所有 AI 简历工具都是"黑盒评分"或"一键生成"。没有一个人在做"告诉你为什么这样改、依据是什么"。

具体要做的事：
- 当前 Demo 已经有"思维链展示"（推理过程），把它从辅助信息升级为**页面主角**
- 每条 AI 建议展示三个锚点：**JD 原话 → 你简历里的对应事实 → 为什么这样改写更好**
- 区分两种 gap：**"你有这个经历但没写好"**（表达缺口）vs **"你确实缺这个经验"**（能力缺口）

**面试时的说法：**
> "我做的不是评分工具，是让 AI 的解释可追溯、可验证。你看这条建议——它告诉你 JD 要求什么、你简历里哪段经历可以支撑、以及改写逻辑。这样面试官追问时你有话可说，而不是说'AI 帮我写的'。"

**实现难度：** 中等。主要是 prompt engineering + 前端展示。不需要改数据模型。

---

### 2. 修改效果验证（Modification Effect Validation）—— “改—验证—再改”闭环

**为什么重要：** 用户修改后需要知道改善了什么、是否新增事实风险、下一步做什么。闭环的价值不是让分数上涨，而是让修改结果可解释、可验证。

具体要做的事：
- 改前/改后的文本 Diff。
- 证据覆盖增加、减少或不变。
- 用户完成一轮修改后统一验证，不在编辑过程中反复调用 AI。
- 分开展示 `improved/unchanged/regressed/tradeoff` 与 PF-002 安全状态；`tradeoff` 表示“有改善，也有新问题”。
- 说明改善点、剩余问题和下一步。
- 分数只作辅助，不作为唯一结论。

**面试时的说法：**
> “通用 AI 给出一版文字就结束了。我让用户主动验证修改效果：系统展示文本变化、证据覆盖和事实风险，再告诉用户下一步。这才是教练式闭环。”

**实现难度：** 中等。现有重评入口可以复用，但需要增加前后快照、证据覆盖、安全状态和结构化反馈。

---

### 3. 简历健康度诊断（Resume Health Check）—— 不依赖 JD 的独立价值

**为什么重要：** 这是 README 路线图里已有的待办项，而且它解决了一个真实场景——用户手里有简历但还没找到具体岗位。独立于 JD 的检查能立即产生价值。

具体要做的事：
- 模糊动词检测："负责"、"参与"、"协助" → 标记为需改写
- 量化缺失检测：经历描述中没有数字 → 提示补充
- 贡献模糊检测：分不清个人贡献 vs 团队成果 → 标记
- STAR 结构检测：是否有 Situation-Task-Action-Result
- 生成一份"简历体检报告"

**面试时的说法：**
> "JD 匹配需要你先有个目标岗位。但我加了一个独立于 JD 的体检功能——它能在 5 秒内告诉你简历的结构性问题：哪里在说废话、哪里缺数据、哪里没讲清楚你的个人贡献。这是任何求职者打开就能用的功能。"

**实现难度：** 低-中。本质是一个独立 prompt + 结果展示页。

---

### 4. 预计算引导演示（Guided Demo）—— 让面试官 30 秒看到产品能力

**为什么重要：** 面试官不会去粘贴 JD 和简历。你要让他们**点一下按钮就能看到产品完整能力**。

具体要做的事：
- 首页增加显眼的“查看演示”入口。
- 使用一个版本化的产品岗黄金案例快照。
- 按真实状态结构回放 JD、事实、缺口、追问、审核和修改验证。
- 明确标记示例数据和预计算结果。
- 不依赖实时 AI，不写入普通历史和真实业务指标。

**面试时的说法：**（不用说，直接展示就行）

**实现难度：** 低到中等。fixture 本身简单，但需要复用真实流程状态，不能只跳到静态结果页。

---

## 锦上添花（有余力再做）

### 5. 面试问题预测
基于 JD-简历 gap 生成可能的面试追问。**价值：** 把产品从"改简历"延伸到"准备面试"，故事更完整。

### 6. 段落级改写建议（2-3 个版本）
对同一段经历，AI 给出稳妥版、强化版、数据驱动版三种表达。**价值：** 展示"AI 不是替代你，而是给你选项"的产品哲学。

---

## 现阶段不要碰的

| 不要做 | 理由 |
|---|---|
| 职业证据库 | 需要账号体系 + 复杂数据模型，一个人做不完 |
| 账号/登录系统 | 对 Demo 价值为零，面试官不会注册 |
| 多岗位版本管理 | 没有证据库就没有版本管理 |
| 导入/导出 | 基础设施，不展示产品洞察 |
| Word/PDF 排版导出 | 纯工程活，面试讲不出故事 |
| 埋点/指标体系 | 没有用户就没有指标 |
| 完整 PRD 里 MVP 的大部分功能 | 那是团队工作量，不是个人作品 |

## 代码里已有的三个亮点（面试时主动讲）

### 1. 后处理校验逻辑（matchAnalyzer.js `_validate()`）

做了 5 层校验：分数 clamp、等级 vs 分数一致性检查、维度异常偏差告警（>40 分）、维度平均分替代异常总分、字段缺省值填充。这不是简单的"调 API 返回结果"——这是**防御性后处理**。

> "LLM 的输出不可靠。我加了一层 validator，做了分数 clamp、等级一致性校验、维度偏差检测和修正。这不是信任 AI，而是把 AI 当不可靠的传感器来用。"

### 2. 思维链 prompt 设计

`MATCH_ANALYSIS_PROMPT` 不只是让 AI 打分，而是强制它走 5 步推理链：明确 JD 要求 → 概括简历事实 → 逐项比对 → 分类优劣 → 给出建议。而且在 prompt 里嵌入了完整示例（含 barrier/learnability 评估）。

### 3. 通用 vs 垂直能力区分

每个 comparison 都标注 category（通用/垂直），差距项评估 barrier + learnability。意味着产品不只是说"你缺这个技能"，而是说"这个技能缺了影响大不大，值不值得花时间补"。

## 面试官可能挑战的点（需要预先准备回答）

- **没有测试。** 零。matchAnalyzer 的 `_validate` 方法非常适合单元测试，但没写。这是最大的扣分项。
- **`_loadSynonyms` 是同步读取。** 每次分析都 `fs.readFileSync` 阻塞读文件。虽然只在构造时触发一次（有缓存），但文件 I/O 不应该出现在 AI 请求链路中。
- **OCR 和文件解析完全依赖第三方库，没有降级方案。** Tesseract.js 对中文 OCR 效果一般，但没有做任何结果校验或 confidence 阈值。

---

## P0 工程改进：给 `matchAnalyzer._validate()` 写单元测试

这是性价比最高的一件事。20 个测试用例，覆盖：
- 分数越界 → clamp
- 等级与分数不一致 → 修正
- 维度偏离 >40 → 告警（不修正，spy console.warn）
- 维度平均分与总分差值 >15 → 用平均分替代
- requirementChecklist status 非法值 → 默认 unmatched
- sectionAnalysis 缺少新结构化字段 → 默认值填充

**为什么这个优先级最高：** 面试官看代码，第一个问题就是"有没有测试"。说"没有"就输了。你有一个天然适合测试的纯函数模块（`_validate`），写测试的成本极低，收益极大。

## 最终优先级排序

| 优先级 | 事项 | 工作量 | 面试价值 |
|---|---|---|---|
| 1 | `_validate` 单元测试（20个用例） | 半天 | ★★★★★ |
| 2 | 证据追溯链升级（prompt + UI） | 2-3天 | ★★★★★ |
| 3 | 修改效果验证（Diff + 证据覆盖 + 安全状态） | 中等 | ★★★★ |
| 4 | 简历健康度体检（独立 prompt） | 1-2天 | ★★★★ |
| 5 | 预计算引导演示（真实状态 fixture） | 低-中 | ★★★★ |
| 6 | 面试问题预测 | 1天 | ★★★ |

具体排期应在 PF-003 状态结构和现有代码改造方案确认后重新估算。

## 总结：你要讲的故事

用一句话概括你的作品：

> **"我不是做了个 AI 评分工具，我是做了个让你能跟面试官解释'我为什么这样写简历'的教练。"**

支撑这个故事的三根柱子：
1. **证据追溯** — 每条建议都能追溯到 JD 要求和你的真实经历
2. **迭代闭环** — 改了能看效果，不是一次性黑盒
3. **独立体检** — 不投具体岗位也能发现简历的结构性问题

这三个功能加在一起，体现了三个层次的产品思考：
- 对 AI 能力边界的理解（不能替代用户判断）
- 对用户真实场景的理解（改简历是迭代过程，需要反馈循环）
- 对信任问题的理解（AI 建议必须可解释、可验证）

这比"我做了个六维雷达图匹配工具"强 10 倍。
