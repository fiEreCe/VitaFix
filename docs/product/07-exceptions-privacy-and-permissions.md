# 精投助手异常、隐私与权限规则

## 1. 文档目标

定义失败场景的用户反馈、恢复动作和数据保留，以及简历、JD、职业证据、联系方式和 AI 数据的权限与隐私规则。

## 2. 异常处理原则

1. 不丢失用户已确认事实和手工文本。
2. 单个 AI 步骤失败不要求重走完整流程。
3. 提示必须说明发生了什么、保留了什么、下一步能做什么。
4. 高影响删除、覆盖和重新生成需要明确确认。
5. 用户可返回工作台，后台任务继续并保留状态。
6. 不向用户暴露服务商原始错误、密钥、堆栈或完整模型输出。

## 3. 异常场景

| ID | 场景 | 用户提示要点 | 可执行操作 | 数据保留 | 恢复位置 |
|---|---|---|---|---|---|
| E-001 | 文件格式不支持 | 支持 PDF/DOCX/TXT；`.doc` 需转换 | 重新选择/粘贴文本 | 不保存文件 | P-010 |
| E-002 | 文件超过 20MB | 文件过大 | 重新选择/压缩/粘贴 | 不保存文件 | P-010 |

| E-005 | 简历信息过少 | 无法建立足够证据 | 补充课程/项目/实习/竞赛 | 保留已有内容 | P-011/P-013 |

## 4. 任务恢复规则

- 每个 AI 步骤有独立 taskId 和状态。
- 自动重试只针对网络、429、5xx 和 Schema 失败，达到上限后停止。
- 用户点击重试复用同一业务对象，不能重复生成岗位版本或任务。
- 失败后保留输入快照和用户确认记录；完整简历内容不写入普通错误日志。
- 后台完成后更新工作台状态，前端可轮询；后续可升级 SSE。

## 5. 当前身份与权限

### 5.1 当前方式

当前前端在 localStorage 生成设备 ID，通过 `X-User-Id` 请求头隔离分析历史，无注册登录。

### 5.2 目标权限规则

1. 所有 BaseResume、JD、Evidence、ApplicationVersion、Task、ChangeRecord 和检查对象都必须关联 userId。
2. 所有读取、更新、删除和 AI 任务接口都校验所有权。
3. 不因知道对象 ID 就可读取数据。
4. 无权限与不存在对外使用一致或不泄露信息的错误响应。
5. 客服或开发调试访问必须有明确授权、审计和最小权限。

### 5.3 当前实现差距

- 当前只有 Analysis 模型存储 userId。
- 历史列表、重命名和删除做了所有权过滤。
- Analysis 详情、状态和重评估目前按 ID 查询，未在控制器中同时校验 userId。
- JD、Resume、Supplement 目前没有 userId，获取和更新接口也没有所有权校验。

上述问题在公开处理真实简历前属于 P0 安全整改。

## 6. 隐私与数据使用

### 6.1 采集范围

仅采集完成简历教练任务所需的简历文本、JD、职业证据、修改记录、任务状态和产品埋点。联系方式不是匹配核心输入，应最小化存储和展示。

### 6.2 使用目的

- 解析和组织职业证据。
- 分析目标岗位要求。
- 生成、审核和解释简历修改。
- 保存用户进度和岗位版本。
- 统计产品质量和故障，不默认用于模型训练。

### 6.3 模型训练

不使用用户简历、JD 或职业证据训练模型，除非另行获得明确、可撤回的授权。授权不能与使用核心功能捆绑。

### 6.4 第三方 AI

在隐私说明中披露会将必要文本发送至第三方模型服务商，并说明目的、范围和适用的数据处理规则。发送前应尽量减少无关个人身份信息。

### 6.5 日志

- 普通日志记录对象 ID、任务类型、耗时、版本、状态和错误码。
- 不记录完整简历、联系方式、JD 原文、API Key 和完整模型响应。
- 调试访问必须受控并有保留期限。

## 7. 数据保留

当前 Demo 声明并实现“分析相关数据 7 天后清理”，但目标产品需要长期复用职业证据库，两者冲突。

发布目标 MVP 前必须确定：

- 原始上传文件是否即时删除。
- 提取文本、职业证据库、岗位版本和日志分别保留多久。
- 无登录用户如何查看和执行删除。
- 过期策略是否支持用户主动延长或立即删除。

在策略确定前，不得在正式文案中承诺与实现不一致的期限。

## 8. 删除与影响

| 操作 | 目标行为 |
|---|---|
| 删除单条经历 | 二次确认；显示受影响岗位版本；相关表达标记来源失效 |
| 删除岗位版本 | 删除该版本的 JD、匹配、任务、表达、检查和学习记录；不删除共享证据 |
| 删除基础简历 | 若证据库依赖该来源，提示影响并要求确认；具体软删除策略待技术设计 |
| 删除全部职业档案 | 删除或匿名化全部用户拥有数据；显示不可恢复警告 |
| 撤回训练授权 | 停止后续使用；历史已进入训练流程的数据处理按授权协议执行 |

## 9. 用户风险控制

- 产品不主动生成红色无依据内容。
- 用户手动输入红色内容时必须持续显示风险和来源缺失。
- 是否允许带阻断风险完成岗位版本是 P0 产品决策；当前建议不允许进入“已完成”，但允许保存草稿和复制由产品评审确认。
- 面试可解释性检查使用“为什么、本人做了什么、结果如何证明”三问。

## 10. P0 待决策

- 身份系统与跨设备恢复。
- 各类数据保留期限。
- 用户手写红色内容的保存/复制边界。
- 客服调试访问流程。
- 隐私政策与第三方模型披露文本。
