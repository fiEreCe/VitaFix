# V0.1 修改效果验证模块规格

## 1. 文档目的

本文件是 V0.1 求职作品版 `PF-003 修改效果验证` 的功能、状态和业务规则唯一事实来源。

PF-003 负责回答：

> 用户修改一段简历后，究竟改善了什么、是否仍有事实风险、还需要做什么？

PF-003 不是独立的黑盒重新评分器，也不会在用户每次编辑后自动运行。

## 2. 核心定位

PF-003 将 PF-001 的单次修改结果组织为“修改—验证—继续”的闭环：

1. 用户连续修改一个简历板块，系统只保存草稿，不在编辑过程中验证。
2. 用户认为本轮修改完成后，主动触发“完成修改并验证”。
3. 系统比较修改前后文本和证据覆盖。
4. 系统检查相关性、真实性和表达质量。
5. 系统说明改善点、剩余问题和下一步。

分数可以作为辅助信息，但不得成为唯一结论、完成条件或主要成功信号。

## 3. 范围

V0.1 包含：

- 单个简历板块完成一轮修改后的统一验证。
- 修改前后文本 Diff。
- 主要能力方向和证据覆盖变化。
- PF-002 红线事实检查。
- 改善点、剩余问题和下一步。
- 验证失败时保留修改前快照和用户文本。

V0.1 不包含：

- 用户每次输入后的自动审核。
- 整份简历的批量重新评估。
- 长期版本历史和任意版本恢复。
- 以分数上涨作为任务完成条件。
- PF-006 的多文风、多版本生成。

## 4. 触发与输入

PF-003 只在用户认为本轮修改完成并点击“完成修改并验证”时运行。编辑、自动保存和普通手工保存均不触发验证。

输入包括：

- JD 要求及原文。
- 修改前文本。
- 用户当前文本。
- PF-001 已确认事实及主要来源。
- 原内容来源和原审核状态。
- 用户风险确认状态。
- 当前缺口类型。

用户开始编辑 AI 候选后，当前文本立即标记为“用户编辑、未经验证”。PF-003 不得沿用修改前的审核通过状态。

本轮比较基线为上一次完成或验证的文本；首次验证时为进入任务时的原文。自动保存草稿不会移动比较基线。系统同时保留任务最初原文作为总体参考。

## 5. 主流程

1. 用户连续修改并自动保存草稿，系统不调用 AI。
2. 用户点击“完成修改并验证”。
3. 保存本轮比较基线和当前用户文本。
4. 程序计算确定性的文本 Diff，并检查 Schema、数字状态和引用存在性等确定性规则。
5. 发起一次 PF-003 语义评估，统一判断证据覆盖、岗位相关性、表达质量和需要语义理解的事实风险。
6. 服务端综合确定性规则与语义评估，生成修改效果和安全状态。
7. 返回改善点、剩余问题和下一步。
8. 追加一条不可变验证记录。
9. 用户选择采用当前文本、继续修改、补充事实或保留风险内容。

不再为同一次 PF-003 验证额外调用第二个 PF-002 审核模型。PF-002 的确定性红线和状态语义继续适用。

验证失败不得覆盖本轮比较基线，也不得丢失用户当前文本。

## 6. 双轴结果

PF-003 使用两个相互独立的结果维度。

### 6.1 修改效果

| 状态 | 含义 |
|---|---|
| `improved` | 证据表达、岗位相关性或表达质量得到明确改善 |
| `unchanged` | 修改没有产生可说明的有效变化 |
| `regressed` | 证据覆盖、相关性或表达质量下降 |
| `tradeoff` | 有改善，也有新问题；至少一个维度改善，同时另一个维度退化或出现新的非红线问题 |

### 6.2 安全审核

沿用 PF-002：

- `passed`
- `warning`
- `blocked`
- `unavailable`

页面中文展示：

- `improved`：有明确改善。
- `unchanged`：暂无明显变化。
- `regressed`：效果有所下降。
- `tradeoff`：有改善，也有新问题。

修改效果不代表安全审核通过；即使结果为 `improved` 或 `tradeoff`，只要新增未确认数字或错误归因，仍然必须 `blocked`。

## 7. 输出

必须输出：

- 修改前文本。
- 修改后文本。
- 文本 Diff。
- `changeOutcome`。
- `safetyStatus`。
- 证据覆盖变化。
- 改善点。
- 剩余问题。
- 下一步。
- 主要事实来源和对应 JD 要求。

可选输出：

- 分项判断变化。
- 辅助分数及变化。

如果展示分数，必须同时展示变化原因；不得只显示“75 → 82”。

## 8. 验证状态与任务完成

- 用户开始编辑后，文本显示“用户编辑 · 未经验证”。
- `passed`：显示“已验证”，可以无风险完成任务。
- `warning`：显示“已检查 · 有风险提示”，不得使用“已验证”。
- `blocked`：显示“存在事实风险”，不得标记为已验证或无风险完成。
- `unavailable`：显示“暂未完成验证”，允许重试。
- `blocked` 不阻止用户保存、复制或继续使用自己的文本；用户坚持保留时，任务进入 `completed_with_risk`。

用户在验证完成后再次编辑，最近一次验证状态立即失效；用户认为下一轮修改完成后，再次点击“完成修改并验证”。

## 9. 用户操作

用户可以：

- 采用当前文本。
- 根据反馈继续修改。
- 返回补充或修正确认事实。
- 保留风险内容并继续。
- 放弃本次修改，恢复修改前文本。

系统不得因为用户保留风险内容而伪造通过状态。

## 9.1 验证记录

- 每次点击“完成修改并验证”都追加一条不可变验证记录。
- 每条记录保存本轮基线、当前文本、Diff、两个结果维度、反馈、模型/Prompt/Schema/规则版本和时间。
- 页面默认只展示最新结果，同时允许查看任务最初原文。
- V0.1 不提供任意历史版本之间的自由比较界面。
- 自动保存草稿不创建验证记录。

## 10. 异常与恢复

| 场景 | 处理 |
|---|---|
| Diff 计算失败 | 保留两个文本版本，提示重试 |
| AI 评估超时或不可用 | 返回 `unavailable`，保留文本和快照 |
| Schema 失败 | 有限重试当前步骤，不展示非法结果 |
| 安全审核阻断 | 展示具体风险和可执行下一步 |
| 页面刷新 | 恢复修改前快照、当前文本和最近一次验证状态 |

## 11. 当前实现差距

当前单板块重评能力可以复用调用入口和部分 UI，但仍存在：

- 以匹配分数为核心。
- 直接覆盖旧板块分析，没有完整修改前快照。
- 未保存用户最终文本和修改记录。
- 没有证据覆盖变化。
- 没有 PF-002 安全状态和验证状态恢复。
- 没有改善点、剩余问题和下一步的稳定结构。
- 没有一次语义评估与确定性规则组合的执行边界。
- 没有不可变验证记录和 `completed_with_risk` 状态。

因此当前实现只能作为迁移起点，不能直接视为 PF-003 完成。

## 12. 验收标准

### AC-PF003-001 完成后统一验证

用户可以连续编辑和自动保存；只有用户认为本轮完成并点击“完成修改并验证”才触发 PF-003。

### AC-PF003-002 前后快照

系统保留修改前文本和当前文本，失败时两者都不丢失。

### AC-PF003-003 修改效果

系统返回 `improved`、`unchanged`、`regressed` 或 `tradeoff`，并提供具体原因。

### AC-PF003-004 安全独立

修改效果与安全状态独立；表达改善不能绕过 PF-002 红线。

### AC-PF003-005 反馈完整

结果包含 Diff、证据覆盖变化、改善点、剩余问题和下一步。

### AC-PF003-006 分数降级

分数只作辅助；没有分数时核心闭环仍可完成。

### AC-PF003-007 验证状态

用户编辑后移除原验证状态；只有 `passed` 显示“已验证”，`warning`、`blocked` 和 `unavailable` 使用各自明确文案。

### AC-PF003-008 异常恢复

超时、Schema 失败和审核不可用不覆盖原状态或丢失用户文本。

### AC-PF003-009 单次语义评估

一次 PF-003 运行只发起一次语义评估调用；Diff、Schema、数字状态和引用存在性由程序处理。

### AC-PF003-010 风险完成

`blocked` 不阻止用户保存和使用自己的文本，但只能以 `completed_with_risk` 完成，不能获得已验证状态。

### AC-PF003-011 版本记录

每次主动验证追加不可变记录；自动保存草稿不创建验证记录，页面默认展示最新结果。
