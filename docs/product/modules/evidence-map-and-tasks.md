# 证据地图与修改任务模块规格

## 1. 模块目标

把已确认岗位要求与职业证据逐条连接，区分表达问题和真实能力缺口，并生成有收益、有依据、可执行的修改任务。

## 2. 模块边界

### 本模块负责

- 检索与岗位要求相关的职业证据。
- 判断证据强度和匹配状态。
- 区分表达缺口、待确认事实和真实能力缺口。
- 创建、排序和更新修改任务。
- 事实或 JD 变化后局部重新评估。

### 本模块不负责

- 创建/确认原始职业事实。
- 生成最终修改文案。
- 组装整份简历。

## 3. 输入与输出

### 输入

- 已确认 JobDescription 和 JobRequirement。
- 已确认职业证据，以及可谨慎使用的黄色证据。
- 基础简历当前表达。

### 输出

- 每条要求的 EvidenceMatch。
- 证据覆盖摘要。
- ModificationTask 列表。
- 无证据项的能力缺口和学习建议入口。

## 4. 功能清单

| ID | 功能 | 输出 | 优先级 |
|---|---|---|---|
| EM-001 | 要求—证据检索 | 候选证据列表 | P0 |
| EM-002 | 证据强度判断 | green/yellow/red | P0 |
| EM-003 | 匹配状态判断 | strong/weak/needs_confirmation/no_evidence | P0 |
| EM-004 | 缺口诊断 | 表达/待确认/能力缺口 | P0 |
| EM-005 | 修改任务生成 | 任务、原因、收益、来源 | P0 |
| EM-006 | 任务优先级 | high/medium/not_recommended | P0 |
| EM-007 | 局部重新评估 | 更新匹配和任务 | P0 |
| EM-008 | 覆盖摘要 | 强证据/部分/无证据数量 | P0 |

## 5. 匹配判断

| 状态 | 条件 | 下一步 |
|---|---|---|
| strong | 有已确认完整任务证据，或客观门槛明确满足 | 生成表达优化任务或无需修改 |
| weak_expression | 有真实证据，但原简历没有体现或表达弱 | 高收益修改任务 |
| needs_confirmation | 可能有相关经历，但角色/行动/结果缺失 | 发起证据追问 |
| no_evidence | 用户确认没有相关经历，或只有红色信息 | 标记能力缺口，不生成虚假任务 |

同一要求可引用多条证据；同一证据也可支撑多个要求，但每个判断都保留独立理由。

## 6. 表达缺口与能力缺口

### 表达缺口

用户真实做过，但：

- 简历未写。
- 只写了职责，没有行动或结果。
- 工具脱离使用场景。
- 个人贡献和团队成果没有说清。
- 相关内容位置过低。

### 真实能力缺口

用户没有做过、没有使用过、不能解释或无法证明。系统提供影响、相邻能力和学习建议，但不把缺口自动写入简历。

## 7. 任务生成规则

每条任务必须说明：

- 为什么修改。
- 对应哪个 JD 要求。
- 当前缺少什么。
- 可使用哪些事实。
- 是否需要补充事实。
- 完成后改善什么。
- 不处理的影响。

没有事实来源的任务不得进入“生成表达”状态。

## 8. 优先级

### 高优先级

- 对应核心/必须岗位要求。
- 用户存在可挖掘或已确认的真实证据。
- 当前表达明显影响岗位判断。
- 修改收益高且事实风险可控。

### 中优先级

- 对应重要或加分要求。
- 能改善表达，但不决定核心匹配。
- 需要较多补充，短期收益一般。

### 不建议修改

- 缺少事实依据。
- 与岗位关系弱。
- 可能通过堆关键词提高分数但不提高可信度。
- 会造成错误归因或面试风险。

优先级是规则和 AI 的组合结果；用户可调整同等级顺序，但不能把无证据任务强制变成可生成任务。

## 9. 覆盖摘要

主摘要展示：

- 核心要求数量。
- 强证据覆盖。
- 弱表达。
- 待确认。
- 无证据。

整体匹配分数和六维雷达图可作为迁移期辅助信息，但不作为主目标、任务优先级唯一依据或完成条件。

## 10. 局部重新评估

以下变化触发受影响项重新计算：

- 新事实确认。
- 事实被修改、删除或降级。
- 用户完成修改任务。
- JD 要求被编辑或重新确认。

不相关匹配项保持原版本，避免全量重算导致结果漂移。

## 11. 页面与流程

- 页面：P-030、P-031。
- 流程：F-005、F-006、F-009。

## 12. 异常

- 检索不到证据：显示无证据或待确认，不返回空白页。
- AI 判断失败：保留已完成匹配，允许单条或整批重试。
- 事实来源失效：对应匹配和任务标记失效。
- JD 更新：地图进入过期状态，用户确认后重新生成。

## 13. 当前实现差距

- 当前 requirementChecklist 已有 matched/partial/unmatched 和 matchedSections，可作为 EvidenceMatch 基础。
- 当前 sectionAnalysis 已有通用/垂直分类、差距和建议。
- 当前没有用户确认状态、证据等级、缺口类型和任务对象。
- 当前建议由分析直接输出，没有优先级清单和任务生命周期。
- 当前六维分数是中心展示，目标需降级。

## 14. 验收标准

- 每条核心要求都有状态、来源和下一步。
- 弱表达和真实能力缺口明确区分。
- 无证据要求不生成简历表达任务。
- 高优先级任务能说明收益和事实来源。
- 事实变化只使相关匹配和任务失效。
- 覆盖摘要不以关键词总分替代事实判断。

## 15. 待确认

- 优先级是否允许用户手动修改。
- 总分/雷达图是否在目标 MVP 完全移除。
- 能力学习建议的内容深度和是否进入首版。
