# 岗位版本与 JD 分析模块规格

## 1. 模块目标

把一条目标 JD 转化为经用户确认的岗位方向、职责和可验证要求，并创建独立的岗位投递版本。

## 2. 模块边界

### 本模块负责

- 创建、命名、重命名、归档和删除岗位版本。
- 输入 JD 文本或截图 OCR。
- 解析公司、岗位、方向、职责和要求。
- 将要求分类为五类并标注重要度、必须/加分项。
- 用户确认和重新解析。

### 本模块不负责

- 从职业证据库寻找匹配证据。
- 生成修改任务或候选表达。
- 组装最终简历。

## 3. 岗位版本

每个岗位版本关联：

- 一个基础简历版本。
- 一条经确认的 JD。
- 证据地图、修改任务、岗位简历、最终检查和学习记录。

默认名称为“公司｜岗位｜投递版本 01”；公司或岗位无法识别时允许用户填写。重命名不改变 JD。

## 4. 功能清单

| ID | 功能 | 输入 | 输出 | 优先级 |
|---|---|---|---|---|
| JD-001 | 创建岗位版本 | 基础简历 | ApplicationVersion 草稿 | P0 |
| JD-002 | 粘贴 JD | 文本 | JD 草稿 | P0 |
| JD-003 | 截图 OCR | JPG/PNG | 可编辑文本 | P0 |
| JD-004 | JD 结构化解析 | JD 原文 | 解析草稿 | P0 |
| JD-005 | 岗位方向判断 | JD | 方向和置信度 | P0 |
| JD-006 | 五类要求提取 | JD | JobRequirement 列表 | P0 |
| JD-007 | 用户确认与纠错 | 解析草稿 | 已确认 JD 版本 | P0 |
| JD-008 | 重新解析 | 更新原文 | 新解析版本、失效提示 | P0 |
| JD-009 | 版本管理 | 名称/删除操作 | 更新或删除结果 | P0 |

## 5. JD 输入

- 文本上限建议 10,000 字。
- 截图最大 10MB，支持 JPG/PNG。
- OCR 只负责提取文本，不自动进入 AI 解析。
- OCR 结果必须允许编辑。
- 公司和岗位可手工填写，不要求依赖 AI 成功识别。

## 6. 岗位方向

可选值：

- AI 产品
- C 端产品
- B 端产品
- 增长产品
- 数据产品
- 其他产品方向
- 不确定

AI 返回方向、置信度和简短依据；用户可修改。方向只影响动态能力框架和展示，不删除 JD 原始要求。

## 7. 岗位要求分类

| 类别 | 例子 | 验证方式 |
|---|---|---|
| 基础门槛 | 学历、专业、实习时长、英语 | 客观满足与否 |
| 工具与方法 | SQL、Excel、Figma、A/B 测试 | 是否实际使用及任务深度 |
| 产品核心能力 | 需求分析、用户研究、原型、数据分析 | 是否有完整任务证据 |
| 协作与推动 | 跨团队沟通、项目推进 | 是否有角色、动作和结果 |
| 行业与场景知识 | AI、电商、社交、企业服务 | 是否理解业务并有相关经历 |

每条要求还需保存：

- 原文。
- 归纳文本。
- 核心/重要/一般。
- 必须项/加分项/未知。
- 用户确认状态。

## 8. 应届生适配判断

系统可判断“适合/不适合/不确定”，但必须展示依据，例如明确校招、实习、毕业年限或经验门槛。信息不足时返回不确定，不阻止用户继续。

## 9. 用户确认

用户确认前可：

- 修改公司、岗位和方向。
- 编辑、添加、删除要求。
- 修改类别、重要度和必须/加分项。
- 标记 AI 误解。

确认后才能进入证据匹配。确认操作保存 JD 版本、解析版本和用户改动。

## 10. 重新解析

已确认 JD 被修改时：

1. 保存新原文和解析草稿。
2. 提示原证据地图、任务和检查将失效。
3. 用户确认后创建新 JD 版本。
4. 只在新版本确认后重新匹配。
5. 已完成的用户修改保留为历史，不静默删除。

## 11. 版本删除

删除岗位版本需要二次确认，删除该版本下的 JD、匹配、任务、表达、检查和学习记录，不删除共享基础简历和职业证据。实际物理删除/软删除由隐私与技术设计确定。

## 12. 页面与流程

- 页面：P-001、P-020、P-021。
- 流程：F-003、F-004、F-011。

## 13. 异常

- OCR 无文本：重新上传或粘贴。
- JD 太短/模糊：补充原文或手工确认。
- 解析失败：保留原文并重试。
- 岗位方向不确定：允许继续，降低置信度。
- 无基础简历：转 P-010，并保存返回目标。

## 14. 当前实现差距

- 当前 JD 已支持文本、OCR、公司、岗位、技能、经验、学历、要求和职责。
- 当前解析结果只在 ActionSheet 中预览，要求不能分类、编辑或逐条确认。
- 当前 JD 没有 userId、岗位方向、重要度、版本和确认状态。
- 当前流程先输入 JD 再输入简历；目标工作台建议先建立可复用基础简历。

## 15. 验收标准

- OCR 结果未经用户确认不自动解析。
- 用户可纠正所有核心解析项。
- 每条核心要求可追溯到 JD 原文。
- 未确认 JD 不进入证据匹配。
- 修改已确认 JD 会明确使下游结果失效。
- 删除岗位版本不删除职业证据。

## 16. 待确认

- 应届生适配判断是否在 MVP 中影响流程，还是只提示。
- 同公司同岗位版本号生成规则。
