# PF-001 证据驱动的简历优化 Agent：V0.1 设计

## 目标与范围

本设计实现 V0.1 求职作品版的首个完整纵向闭环：用户提交一份 JD 和简历后，系统分析全文、生成任务列表并推荐一个高优先级任务；用户可经过动态追问、事实确认、AI 候选生成、PF-002 事实审核和最终决策，完成该任务。

本轮同时建设 PF-002 所需的确定性基础设施：结构校验、引用校验、候选事实审核和风险提示。PF-003 只接收并保存标准化交接包，不实现完整的修改效果验证页面。

不在本轮范围内：一次性完成所有任务、长期证据库、账号体系、全量 PF-003、PDF/Word 排版导出和多版本简历生成。

## 方案选择

采用并行新增 Agent 模块的方案：新增 `AgentSession` 领域模型、独立服务、接口和工作台页面；保留现有 JD/简历解析流程与旧 `Analysis` 评分页。

这样可以复用已有解析能力，同时避免将旧的评分中心模型与 Agent 的多步骤状态、恢复和审计记录强耦合。前端从服务端状态渲染，不自行推断状态迁移。

## 会话模型与状态

`AgentSession` 是一次性、可恢复会话的唯一状态来源，按 `userId` 隔离。它保存：

- 已确认的 JD、简历输入快照及解析版本；
- 岗位要求、简历事实、需求—证据匹配、缺口类型和任务优先级；
- 当前任务、有效追问轮数、当前问题、待确认与已确认事实；
- 候选文本、事实和需求引用、PF-002 审核结果、用户决策和风险确认；
- PF-003 交接包及不含模型思维链的状态转换记录。

会话状态为：`draft → parsing → matching → evidence_ready → task_in_progress → ready_for_reevaluation → completed`，并支持 `cancelled` 与 `expired`。

高优先级任务状态为：`pending → assessing_evidence → questioning → awaiting_fact_confirmation → generating → verifying → awaiting_user_decision → accepted | user_edited | rejected | skipped | capability_gap → ready_for_reevaluation`。

每次状态变更记录前后状态、触发事件、工具名、非敏感输入输出摘要、错误类型和耗时；不保存模型思维链、密钥或不必要的完整简历文本。

## Agent 编排与证据规则

服务端编排以下独立步骤：解析 JD、解析简历、建立需求—证据匹配、分类缺口、选择下一问、评估答案、汇总待确认事实、生成候选表达和审核候选表达。每个步骤可独立失败、重试并保留此前确认的数据。

候选生成只能读取当前任务中 `confirmed` 或 `corrected` 的事实。系统以 `strong`、`basic` 和 `insufficient` 划分信息充分度：

- `strong`：包含具体行动、场景或对象、个人职责边界，以及方法或结果之一；可生成完整表达。
- `basic`：包含具体行动、对象和职责边界；只可生成不扩张结果或影响的保守表达。
- `insufficient`：不生成候选，交还继续补充、手动编辑或跳过的选择。

每次仅问一个价值最高的缺失事实。相关或部分相关回答消耗一轮有效追问；答非所问仅有一次不计轮次的澄清；三轮后不强制生成。只有用户明确表示“没有做过”才标记为能力缺口，其余未知、矛盾、答非所问和信息不足都属于信息缺口。

## PF-002 确定性护栏

所有 AI 步骤的结构化输出先经服务端 Schema、枚举、必填字段与引用 ID 校验。候选审核检查：

- 每项事实是否能引用已确认事实；
- 数字是否已确认；
- 团队成果是否被误写成个人成果；
- 职责、工具、结果或项目性质是否被扩大或虚构。

审核结果为 `passed`、`repairable`、`needs_confirmation`、`unsupported` 或 `system_error`。`repairable` 最多自动修正一次；第二次仍失败则停止自动生成并保留原文与事实。

用户编辑内容只接受风险检查和具体提示，不阻断保存或继续使用；它必须标记为 `user_edited`，不能被标示为 AI 已验证事实。

## 接口与界面

新增 Agent 会话 API，职责包括：创建/读取会话、提交并确认输入快照、启动分析、读取状态、选择任务、提交追问回答、确认或修正事实、重试当前失败步骤、生成并审核候选、记录采用/编辑/拒绝/跳过，以及获取 PF-003 交接包。

新增证据驱动优化工作台页面：

- 左侧展示可独立选择的任务列表，突出默认推荐项；
- 主区域展示 JD 原文依据、匹配到的简历原文和已确认事实；
- 追问阶段展示追问原因、当前问题、推荐选项、自由输入与“不记得/没做过/无法证明”；
- 候选阶段同时展示原文、证据、候选、理由摘要和审核结果；
- 决策阶段支持采用、编辑后采用、拒绝、修正事实和跳过。

刷新时通过 `agentSessionId` 恢复会话。失败只影响当前步骤，用户已确认事实和手写文本不得被后续失败覆盖。

## 测试与验收

使用 Node 内置测试运行器。状态机和护栏测试使用确定性工具适配器，不调用真实 DeepSeek 或 MongoDB；线上路径复用 DeepSeek 适配器。

必须先以失败测试覆盖以下规则：

- 未确认事实不得进入候选生成；
- 无依据事实、未确认数字、错误归因和职责扩大不能作为已审核建议展示；
- 答非所问只允许一次不计轮次的澄清；
- 三轮有效追问后不强制生成；
- 只有明确“没做过”进入能力缺口；
- 用户编辑仅提示风险且不阻断保存；
- 步骤失败和刷新后能保留已确认事实与用户文本。

首个可交付版本满足：全文生成任务列表并推荐一项、一个高优先级任务完整跑通、候选只引用已确认事实、PF-002 审核在候选展示前完成、状态可恢复、PF-003 交接包完整可用。
