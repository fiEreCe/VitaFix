# V0.1 Apple 风格响应式前端重构设计

## 1. 目标

本轮将当前“移动端页面套 480px 桌面外壳”的前端重构为真正适配手机、平板和电脑的响应式工作区，同时保留 PF-001 至 PF-004 已通过代码级验收的业务、安全和数据契约。

重构后的产品应让求职者感到冷静、可信和清晰：手机端适合快速触控和线性完成任务，电脑端适合同时查看任务、证据和验证上下文。Apple 风格在本项目中表示即时反馈、空间一致性、克制材料、系统排版和可访问性，不表示堆叠玻璃、装饰性弹跳或模仿原生 iOS 控件。

## 2. 范围

### 2.1 本轮包含

- 首页、JD 输入、简历输入、补充经历、Agent 工作台、分析结果、历史记录和引导演示八个路由页面。
- 全局设计 token、页面容器、响应式断点、排版、焦点、材料、状态和动效规范。
- 手机、平板、普通电脑和宽屏电脑四档布局。
- 键盘操作、文字缩放、屏幕阅读器语义、降动效、降透明度和高对比模式。
- 代表性手机、平板和电脑视口的浏览器渲染验证。
- 与现有业务契约对应的前端自动化回归。

### 2.2 本轮不包含

- 暗色模式。
- 新账号体系、跨设备同步或长期证据库。
- 修改现有 API、Agent 状态机、AI 审核规则或数据库模型。
- 新增拖拽排序、复杂手势、音效或触觉反馈。
- 重写全部 Vant 组件或建立独立发布的通用组件库。
- PF-005、PF-006 或其他新产品功能。

## 3. 设计原则

### 3.1 目的与层级

每个页面优先回答四个问题：用户在哪里、当前要做什么、为什么要做、如何离开或继续。常用路径直接展示，高级信息收在次级层级。视觉层级依靠排版、间距和表面权重建立，不依赖卡片套卡片。

### 3.2 用户控制与安全

所有现有确认、编辑、重试、风险确认和交还控制权行为保持可见。系统不得因为视觉重构隐藏 `blocked`、`warning` 或 `unavailable`，也不得把用户编辑内容继续标记为 AI 已验证。

### 3.3 即时但克制的反馈

- 可点击控件在按下时立即反馈，目标时长为 120ms。
- 内容揭示使用 180ms 左右的淡入或小幅位移。
- 布局和面板变化控制在 260ms 左右。
- 默认不使用弹跳；只有真实的拖拽或甩动才允许速度继承和轻微回弹。本轮没有必须新增的手势场景，因此不引入动效库。
- 只动画 `transform`、`opacity` 和必要的颜色；避免 `transition: all` 和用 `width` 驱动长动画。

### 3.4 材料与深度

内容卡片保持实色，以保证简历文本和证据引用的可读性。半透明材料只用于粘性导航、工具栏和桌面侧栏，并且同一视觉层级只允许一层材料。降透明度模式下使用近实色背景和明确边框。

### 3.5 排版

- 字体使用系统字体栈，包括 `-apple-system`、`BlinkMacSystemFont` 和 `PingFang SC`。
- 正文以 `rem` 为主，默认不小于 0.875rem；关键正文不小于 1rem。
- 大标题采用较紧字距和行高，正文保持舒适中文行高。
- 布局随用户文字缩放自然重排，不通过禁止缩放维持版面。

## 4. 响应式架构

### 4.1 断点

| 范围 | 目标设备 | 布局规则 |
|---|---|---|
| `<600px` | 手机 | 单列，16px 页面边距，触屏优先，关键操作可贴近底部安全区 |
| `600–899px` | 平板和窄窗口 | 单列，24px 页面边距，正文宽度 640–720px |
| `900–1199px` | 普通电脑 | 工作区宽度约 960–1120px，可使用侧栏和主内容双栏 |
| `>=1200px` | 宽屏电脑 | 工作区最大宽度约 1180px，Agent 和结果页可增加上下文辅助栏 |

断点集中在共享布局样式中，页面只声明自身需要的网格区域。移除 `App.vue` 的全局 `max-width: 480px` 限制；手机预览若未来需要，应作为显式演示模式实现。

### 4.2 页面容器

共享页面容器提供：

- 最大宽度、水平边距和安全区。
- 标准页头、返回行为、标题、说明和可选操作区域。
- 单列、主辅双栏和三段工作台三种布局模板。
- 粘性工具栏的滚动边缘阴影或渐变，不使用无条件硬分隔线。

## 5. 页面设计

### 5.1 首页

手机端按品牌价值、主要操作、引导演示、最近记录和隐私说明顺序排列。电脑端采用左右分区：左侧讲清“证据驱动、事实安全、修改可验证”的产品价值与主要入口，右侧展示最近记录或三步闭环摘要。

Emoji 不再承担核心品牌图标职责；使用仓库内 SVG 或 CSS 原生图形，避免平台间度量不一致。主要操作和引导演示保持清晰的主次关系。

### 5.2 JD、简历和补充经历输入

三个页面共享轻量步骤导航，明确当前阶段和下一步。正文编辑区在大屏上限制到适合阅读的宽度，上传和预览可使用更宽区域。OCR 后必须继续允许用户确认和编辑文本。

输入方式选择使用真实按钮或单选语义，不再使用只响应鼠标点击的 `div`。错误就近展示并提供重试；Toast 只作为补充反馈。

### 5.3 Agent 工作台

Agent 工作台是本轮最高优先级页面。

- 手机端：任务概览、当前问题/候选和证据上下文按线性层级展示；关键提交操作可在安全区上方固定，但不得遮挡错误和风险说明。
- 普通电脑：左侧约 280–300px 任务侧栏，右侧为当前任务主区。
- 宽屏电脑：在主区右侧增加约 280–320px 的证据、审核和验证上下文栏。

`AgentWorkbench.vue` 继续负责 API 调用、轮询、状态派生和用户动作。新增子组件只接收 props 和发出明确事件，不复制状态机，也不自行调用 API。建议组件边界为任务导航、当前问题、事实确认、候选审核、修改验证和状态反馈。

### 5.4 分析结果

手机端保持顺序阅读。电脑端使用概览和详情双栏：评分/雷达/核心摘要在较窄概览栏，岗位要求和板块详情在主栏。旧分析数据的 `matchedRequirements` 和 `suggestions` 兼容逻辑继续保留。

### 5.5 历史记录

手机端使用单列卡片。电脑端采用高密度双列或表格式布局，仍保留查看、重命名和带确认的删除。整行点击必须使用链接或按钮语义，并提供明确的键盘焦点。

### 5.6 引导演示

手机端逐步揭示，电脑端同时展示流程轨迹和当前步骤详情。演示继续只从 `fixture.session` 派生，不调用实时 Agent/Analysis API、不写历史、不进入真实 `page_view` 漏斗。

新增步骤可使用 180ms 淡入和轻微位移；降动效模式只淡入或直接出现。重新开始必须回到第一步。

## 6. 设计系统

### 6.1 Token

扩展 `variables.css`，统一以下 token：

- 语义颜色：品牌、成功、警告、危险、信息和各级文字。
- 表面：页面、实色内容、悬浮材料、选中和按压。
- 排版：display、title、headline、body、caption 的字号、字重、行高和字距。
- 间距：以 4px 为基础的有限尺度。
- 圆角、边框、阴影和焦点环。
- 动效时长、缓动和按压缩放。
- 页面宽度、侧栏宽度和层级。

业务状态颜色必须同时配合文字或图标，不允许只靠颜色表达。

### 6.2 共享组件

仅抽取实际跨页面复用的组件：

- 页面框架与页头。
- 状态标签。
- 空、加载、错误和重试状态。
- 必要的粘性操作栏。

不为一次性样式建立抽象，不替换 Vant 已能可靠提供的 Dialog、Action Sheet、Loading 和基础 Button 行为。

## 7. 可访问性

- 从 viewport 移除 `maximum-scale=1.0` 和 `user-scalable=no`。
- 所有可点击 `div` 改为链接、按钮或正确的表单控件。
- 图标按钮提供可访问名称，点击区域至少 44×44px。
- 展开控件提供 `aria-expanded` 和关联区域。
- 自定义控件统一提供高可见 `:focus-visible`。
- 加载和异步完成使用 `role="status"` 或 `aria-live="polite"`；阻断错误使用 `role="alert"`，Toast 不是唯一信息来源。
- 雷达图提供文本摘要。
- 支持至少 200% 页面缩放，不产生关键内容丢失或不可操作的横向溢出。
- 提供 `prefers-reduced-motion`、`prefers-reduced-transparency` 和 `prefers-contrast: more` 降级。

## 8. 必须保留的业务契约

1. 路由地址、参数和 `jdId → resumeId → supplement/skip → agent session id` 顺序。
2. `pendingResumeId`、`pendingJdId` 和刷新恢复逻辑。
3. `skip === '1'` 自动启动分析，以及使用 `router.replace` 防止返回时重复创建会话。
4. `X-User-Id`、`jingzhu_device_id` 和所有用户隔离行为。
5. JD OCR 后先确认文本，不自动越过用户确认。
6. Resume 文件类型、上传/解析端点和响应字段。
7. 全部 Agent 状态枚举、失败重试和交还控制权语义。
8. 用户编辑内容未经自动验证；风险内容只能显式确认；审核不可用不得显示通过。
9. 旧分析数据字段兼容。
10. 历史记录查看、重命名、删除确认和埋点。
11. GuidedDemo 静态 fixture、无实时 API、无历史写入和漏斗隔离。
12. 结构化、字符串和非 JSON API 错误兼容。

## 9. 错误和状态反馈

页面统一区分加载、空状态、可重试错误、不可重试错误、成功、警告、阻断和暂不可用。结构化错误继续使用 `message/code/retryable`，旧字符串和非 JSON 响应保持兼容。

错误显示靠近受影响内容，并保留用户已经输入的 JD、简历、回答或修改文本。重试动作只重试失败步骤，不重新执行已经完成的生成或审核。

## 10. 测试与验证

### 10.1 自动化

- 保留现有前端 4 个契约测试、后端 114 个测试和 PF-002 42 个固定评测。
- 使用测试先行方式覆盖共享布局、可访问语义和关键业务契约。
- 为 `AgentWorkbench` 拆分组件增加 props、事件和状态呈现测试。
- 为 GuidedDemo 增加第一步、逐步推进、重启、静态 fixture 和无实时 API 回归。
- 生产构建必须通过且无新增警告。

### 10.2 浏览器验证

至少验证以下视口：

- 手机：390×844。
- 平板：768×1024。
- 电脑：1440×1000。

每个代表性视口检查首页、输入流程、Agent 工作台、分析结果、历史记录和引导演示。检查项目包括：无横向溢出、焦点顺序、触控目标、粘性区域遮挡、长中文换行、200% 缩放、降动效和降透明度。

动态页面通过脱敏 fixture 或浏览器请求拦截验证，不把真实简历写入截图、日志或测试数据。

### 10.3 交叉审查

实施按独立任务拆分给子 agent。每个任务完成后执行：

1. 规格符合性审查。
2. 代码质量、可访问性和 Apple 动效原则审查。
3. 主 agent 检查 diff 并运行聚焦测试。

全部任务集成后再运行全量测试、评测、构建和三档视觉验证。

## 11. 验收标准

1. 八个路由在手机、平板和电脑上均有符合本设计的布局，不再是固定 480px 手机壳。
2. Agent 工作台在电脑端至少使用任务侧栏和主内容双栏，宽屏可同时查看证据或验证上下文。
3. 所有原有业务、安全、路由、API 和演示隔离契约保持通过。
4. 禁止缩放和主要非语义点击元素被修复，键盘焦点和异步状态可感知。
5. 动效遵守即时、克制、可中断原则，并提供降动效/降透明度/高对比降级。
6. 后端测试、PF-002 固定评测、前端测试和生产构建全部通过。
7. 390×844、768×1024 和 1440×1000 的代表性页面完成渲染检查，无阻塞缺陷。
8. 不引入真实简历、凭据、模型敏感原始输出或无关产品功能。
